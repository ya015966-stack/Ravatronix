# طراحی فنی سرور لحظه‌ای RAVA

**پروژه:** Ravatronix  
**نسخه سند:** 1.0  
**تاریخ:** ۷ نوامبر ۲۰۲۶

## ۱. هدف

ایجاد یک سرور مرکزی برای ارتباط دوطرفه و لحظه‌ای بین ربات ESP32-S3 و سرویس آنلاین RAVA، بدون ایجاد تغییر در فریمور فعلی دوربین.

## ۲. معماری پیشنهادی

- **Backend:** Node.js
- **میزبانی:** Render
- **ارتباط لحظه‌ای:** WebSocket امن (WSS)
- **پروتکل درخواست‌های معمول:** HTTPS
- **دوربین:** مسیر مستقل برای دریافت تصویر و حفظ جریان فعلی دوربین

ارتباط ربات با سرور از داخل شبکه آغاز می‌شود؛ بنابراین نیازی به IP عمومی برای ESP32 یا بازکردن پورت روی هات‌اسپات گوشی نیست.

## ۳. اجزای سرور

### سلامت سرویس
`GET /health`

وضعیت فعال‌بودن سرور را گزارش می‌کند.

### ارتباط WebSocket
`WSS /ws`

وظایف:
- دریافت پیام متنی از ربات
- ارسال پاسخ سرور به ربات
- ارسال فرمان‌ها و وضعیت‌ها
- تشخیص قطع ارتباط و مدیریت اتصال مجدد
- احراز هویت دستگاه هنگام اتصال

### دریافت تصویر
`POST /api/camera`

دریافت تصویر ارسالی از ربات از طریق HTTPS. این مسیر از کانال پیام WebSocket جدا می‌ماند تا انتقال تصویر، ارتباط متنی را مختل نکند.

### پیام متنی
پیام‌های متنی و پاسخ‌های هوش مصنوعی از طریق WebSocket منتقل می‌شوند. اتصال به ارائه‌دهنده هوش مصنوعی در مرحله بعد انجام خواهد شد.

## ۴. قالب پیام‌ها

پیام‌ها با JSON منتقل می‌شوند.

نمونه پیام ربات:

```json
{
  "type": "chat",
  "device_id": "rava-001",
  "message_id": "msg-001",
  "text": "سلام RAVA"
}
```

نمونه پاسخ سرور:

```json
{
  "type": "chat_response",
  "message_id": "msg-001",
  "text": "سلام! صدات رو دریافت کردم."
}
```

## ۵. امنیت

- استفاده از TLS و اتصال WSS
- احراز هویت هر دستگاه
- نگهداری کلیدهای محرمانه در Environment Variables سرور
- عدم قرار دادن کلید هوش مصنوعی در فریمور
- محدودیت اندازه پیام و تصویر
- اعتبارسنجی ورودی‌ها

هیچ رمز یا کلید واقعی در این سند قرار نمی‌گیرد.

## ۶. مدیریت خطا و اتصال مجدد

- تلاش مجدد با فاصله افزایشی پس از قطع ارتباط
- ارسال پیام Ping/Pong برای بررسی زنده‌بودن اتصال
- شناسه یکتا برای پیام‌ها
- گزارش خطا در سمت سرور
- جلوگیری از ارسال بی‌نهایت پیام تکراری

## ۷. ترتیب پیاده‌سازی

1. ساخت سرور Node.js و مسیر سلامت
2. پیاده‌سازی WebSocket و احراز هویت
3. آزمایش ارتباط دوطرفه با کلاینت آزمایشی
4. اتصال ESP32 به سرور با WSS
5. آزمایش قطع و وصل مجدد
6. اضافه‌کردن مسیر دریافت تصویر
7. اتصال موتور هوش مصنوعی آنلاین در مرحله بعد

## ۸. معیارهای پذیرش

- سرور از اینترنت قابل دسترسی باشد.
- ربات بتواند اتصال WSS برقرار کند.
- پیام ربات به سرور برسد.
- پاسخ سرور بدون درخواست مجدد به ربات برسد.
- قطع و وصل اینترنت باعث ازکارافتادن دائمی ارتباط نشود.
- فریمور فعلی دوربین تا زمان موفقیت آزمایش‌ها دست‌نخورده بماند.

## ۹. خارج از محدوده این فاز

- ساخت اپلیکیشن کامل اندروید
- راه‌اندازی تماس صوتی زنده
- کنترل موتورها
- اتصال نهایی به مدل هوش مصنوعی
- تغییر فریمور دوربین

این قابلیت‌ها در فازهای بعدی اضافه می‌شوند.
