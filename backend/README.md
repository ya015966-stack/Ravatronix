# Ravatronix backend (phase 1)

Node.js service for the first authenticated connection between RAVA and the cloud.

## Included

- `GET /health`: public service health check.
- `WSS /ws`: authenticated device connection and chat-provider adapter.
- `POST /api/camera`: authenticated JPEG upload (up to 2 MiB). This phase validates and acknowledges the image; it does not persist or forward it.
- Device authentication uses the first WebSocket JSON message, not a URL query parameter, so the secret is not placed in request URLs.
- Optional OpenAI-compatible chat provider; demo mode remains the default.

## Local run

Requires Node.js 20 or newer.

```sh
npm install
RAVA_DEVICE_TOKEN='your-long-random-secret' RAVA_CHAT_MODE=demo npm start
npm test
```

## Chat provider configuration

The default `RAVA_CHAT_MODE=demo` response is explicitly marked as a test response. It is not generated by an AI model.

### Cloudflare Workers AI (prepared configuration)

The existing OpenAI-compatible adapter can call Cloudflare Workers AI without putting provider credentials in the firmware or Android app. When an eligible Cloudflare account is available, configure these values in the backend hosting service's private environment settings:

- `RAVA_CHAT_MODE=openai-compatible`
- `RAVA_AI_BASE_URL=https://api.cloudflare.com/client/v4/accounts/ACCOUNT_ID/ai/v1`
- `RAVA_AI_MODEL=@cf/meta/llama-3.1-8b-instruct` (example model ID; confirm that this model is currently available on the account's free allowance)
- `RAVA_AI_API_KEY=your-private-Cloudflare-API-token`

Replace `ACCOUNT_ID` with the account identifier. Use a token with only the permissions required for Workers AI inference. Keep it private in the server environment; never put it in firmware, Android app code, Git commits, or chat.

This repository change only prepares configuration documentation. It does not create a Cloudflare account, issue a token, activate a model, or verify account eligibility or current free quota. Keep `RAVA_CHAT_MODE=demo` until the account's current terms, age eligibility, regional availability, and free allowance have been checked with a parent or guardian where required. Do not enter payment details or enable paid billing.

### Other OpenAI-compatible providers

For another provider, set:

- `RAVA_CHAT_MODE=openai-compatible`
- `RAVA_AI_BASE_URL=https://provider.example/v1`
- `RAVA_AI_MODEL=the-model-id-issued-by-the-provider`
- `RAVA_AI_API_KEY=the-private-provider-key`

The provider endpoint must use HTTPS. The server sends only the user's current text message and returns the model's text response. The API key stays on the server. Requests have a 15-second timeout and provider errors are returned to the device as a generic `chat_error`; credentials and upstream response bodies are not exposed.

Free service quotas, account eligibility, regional availability, privacy terms, and provider age requirements vary. Do not enable a provider unless its current terms allow the intended use. Free access may be rate-limited or changed by the provider. Never enter payment details or enable paid billing for this project.

## WebSocket handshake

Connect to `wss://YOUR-SERVICE.onrender.com/ws`, then send:

```json
{"type":"auth","role":"device","token":"YOUR_DEVICE_TOKEN"}
```

The server replies with `auth_ok`. A device can then send:

```json
{"type":"chat","message_id":"msg-001","text":"سلام RAVA"}
```

In demo mode the server replies with a clearly labeled test message:

```json
{"type":"chat_response","message_id":"msg-001","text":"حالت آزمایشی فعال است؛ هنوز مدل هوش مصنوعی متصل نشده است.","mode":"demo","provider":"demo"}
```

In AI mode, the response includes `mode: "ai"` and `provider: "openai-compatible"`.

## Camera upload

Send a JPEG body to `POST /api/camera` with:

```
Authorization: Bearer YOUR_DEVICE_TOKEN
Content-Type: image/jpeg
```

The current phase responds with HTTP 202 and the received byte count. It does not store the image.

## Render

Create a Node web service from this repository and branch:

- Root directory: `backend`
- Build command: `npm install`
- Start command: `npm start`
- Health check path: `/health`
- Environment variables: `RAVA_DEVICE_TOKEN` (required); provider variables only if AI mode is enabled.

The service binds to Render's `PORT` and listens on `0.0.0.0`.

## Scope boundaries

This phase does not change the ESP32 camera firmware, implement image understanding, expose a mobile app, store images, or enable motor commands. Those are separate stages after this transport layer is verified.
